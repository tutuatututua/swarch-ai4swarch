## 3. บันทึกผลการตัดสินใจ (8 นาที, ทำร่วมกัน)

> ผู้เขียน ADR ทำหน้าที่สถาปนิก โดยใช้ AI agent ช่วยในอีก 3 บทบาท ได้แก่ AI analyst, Product owner และ SRE บทบาท PO และ SRE เป็นการจำลองจากเอกสาร โดย AI ไม่ได้อ่านการ์ด P/S หรือไฟล์ใดใน docs/review-board/ จึงไม่มีข้อมูลลับจากการ์ดบทบาท

**ADR ที่รีวิว:** `docs/adr/0002-use-rabbitmq-for-order-events.md` โดย ผู้เขียน ADR (A: Deciders)

**สมาชิกและบทบาท:**

| บทบาท | ผู้ทำหน้าที่ | ข้อมูลที่ใช้ |
|---|---|---|
| สถาปนิก | ผู้เขียน ADR | นำเสนอและปกป้องข้อเสนอใน ADR |
| AI analyst | agent `ai_analyst` | ถ่ายทอด Findings table และ Verdict จากผลรีวิวเดิมแบบคำต่อคำ โดยไม่เพิ่มความคิดเห็น |
| Product owner | agent `product_owner` | อนุมานข้อกังวลธุรกิจจาก ADR และผลรีวิว ไม่มีข้อมูลการ์ด P |
| Site reliability engineer (SRE) | agent `sre` | อนุมานข้อกังวลปฏิบัติการจาก ADR และผลรีวิว ไม่มีข้อมูลการ์ด S |

**หลักฐาน:** **A** = `docs/adr/0002-use-rabbitmq-for-order-events.md`; **R** = `exercise/outputs/3-review.md` การอ้างชื่อหัวข้อด้านล่างหมายถึงหัวข้อในสองไฟล์นี้ ข้อกล่าวถึง scenario และ source code เป็นข้อมูลที่ A/R รายงาน ยังไม่ได้ตรวจสอบไฟล์ต้นทางโดยตรง

**สรุปการนำเสนอของสถาปนิก:** เลือก outbox และ RabbitMQ เพื่อบันทึกคำสั่งซื้อพร้อมเหตุการณ์ก่อนตอบสำเร็จ แล้วแยกงานอีเมล แต้ม และ analytics ไปยังคิวของแต่ละงาน ข้อเสนอยังมีสถานะ `Proposed` และ Validation เป็นแผนที่ยังไม่มีผลทดสอบ (A: Status, Decision, Validation)

| ทางเลือก | ข้อดี [Inferred] | ข้อเสีย [Inferred] |
|---|---|---|
| synchronous ผ่าน gRPC | ใช้ทักษะเดิม เพิ่มโครงสร้างพื้นฐานน้อย | การรอ MailFast เสี่ยงเกินเป้า latency; timeout แล้วทิ้งงานไม่รับประกันความครบถ้วน |
| worker กลางกับแหล่งเก็บงาน | นำงานออกจากเส้นทางตอบกลับ ติดตามสถานะและ retry ได้ | ต้องสร้างการจองงานและกู้คืนเอง พร้อมแยกกำลังประมวลผลไม่ให้อีเมลขวางแต้ม |
| outbox และ RabbitMQ | แยกคิวและ retry ต่อประเภทงาน เพิ่มผู้รับเหตุการณ์ได้ | เพิ่ม broker และแหล่งเก็บข้อมูล ต้องดูแลข้อความซ้ำและ schema |

หลักฐานทั้งตาราง: A, Considered options และ Pros and cons of the options

**มติ:** อนุมัติโดยมีเงื่อนไขให้แก้ไข — เป็นข้อเสนอจากผลรีวิวเพื่อให้สถาปนิกพิจารณา โดย AI analyst ถ่ายทอดคำตัดสินเดิม และยังไม่ยืนยันความพร้อมใช้งานจริง (R: Verdict; A: Validation)

**สิ่งที่ต้องแก้ไข:**

1. เลือกแหล่งเก็บคำสั่งซื้อ/outbox ระบุจุด commit สัญญา request idempotency และการกู้คืนหรือชดเชยเมื่อชำระเงินหรือจัดส่งแล้วบันทึกไม่สำเร็จ พร้อมผลทดสอบจุดล่ม — เพื่อความถูกต้องและความสามารถในการกู้คืน (A: Open questions, Validation ข้อ 4; R: Verdict ข้อ 1)
2. ตกลงขอบเขต outage ของเกณฑ์แต้ม 60 วินาที กำหนดสูตรและข้อมูลคำนวณแต้ม พร้อมทดสอบทั้งจำนวนแต้มที่ถูกต้องและการไม่ให้แต้มซ้ำ; กำหนดความหมาย/schema และเวลาส่ง analytics ที่ยอมรับได้ — เพื่อความถูกต้อง ความครบถ้วน และความทันเวลา (A: Open questions, Validation ข้อ 2; R: Verdict ข้อ 2; ส่วนสูตรแต้มและ schema เป็นข้อเสนอเพิ่มเติมจาก PO จำลอง)
3. กำหนดระยะพีก เวลารออีเมล นโยบายอีเมลซ้ำ ความจุ retention ผู้ดูแล topology และเป้าหมายกู้คืน พร้อมผลทดสอบโหลด การระบายงานค้าง และ backup/restore; เปรียบเทียบภาระดูแล worker กลางกับ RabbitMQ ด้วยเกณฑ์เดียวกัน — เพื่อประสิทธิภาพ ความพร้อมใช้งาน ความสามารถในการดูแล และต้นทุน (A: Considered options, Open questions, Validation; R: Missing or weak, Verdict ข้อ 3; ส่วน backup/restore เป็นข้อเสนอเพิ่มเติมจาก SRE จำลอง)

**ใครยกประเด็นใด** — ข้อกังวลเป็น [Inferred] จาก A/R ไม่ใช่ข้อมูลจากการ์ดบทบาท

**ข้อค้นพบที่ดีที่สุดของ AI** (ที่มนุษย์มองข้ามไป): ในการจำลองนี้เลือกข้อขัดแย้งระหว่างเส้นตายแต้ม 60 วินาทีกับ outage ที่ยาวกว่า เพราะต้องแก้ขอบเขตข้อกำหนด การแจ้งเตือนอย่างเดียวไม่แก้ปัญหา (R: Findings table, Risk เรื่องแต้ม) อย่างไรก็ตาม ยังยืนยันไม่ได้ว่ามนุษย์มองข้ามจริงหรือไม่: ไม่พบหลักฐานยืนยันในไฟล์ที่ให้มา

**ข้อค้นพบที่อ่อนที่สุดของ AI** (กว้างเกินไป ผิด หรือไม่เกี่ยวข้อง): [Inferred] การจัดแนวทาง outbox และคิวแยกเป็น Non-risk มีน้ำหนักจำกัดสำหรับอนุมัติใช้งาน เพราะยังเป็นการประเมินระดับแนวทาง ผลรีวิวเองระบุว่าต้องวัดผลเมื่อใช้ทรัพยากรร่วมกัน และ ADR ยังไม่มีผลทดสอบ จึงไม่ใช่ข้อค้นพบที่พิสูจน์ว่าผิด แต่ยังไม่เพียงพอยืนยันว่าผ่านเป้าหมาย (R: Findings table แถวแรก; A: Validation)

**ข้อจำกัดของผลการจำลอง:** สูตรแต้มและ backup/restore เป็นตัวอย่างประเด็นที่ผลรีวิวเดิมกล่าวไม่ครบ แต่ AI สามารถอนุมานได้จาก ADR จึงยังตอบไม่ได้ว่าคณะกรรมการมนุษย์พบอะไรจากข้อมูลที่ AI ไม่เคยเห็น ข้อจำกัดจากการ์ด P/S และผลการประชุมคณะกรรมการมนุษย์เพิ่มเติม: ไม่พบหลักฐานยืนยันในไฟล์ที่ให้มา
